# Local board firmware

Bare-metal benchmark firmware for our own boards, used to repeat the ST Edge AI Developer
Cloud measurements on hardware we hold and, with a current meter, to measure energy per
inference. One firmware image per network: the network is generated by the local ST Edge AI
Core, linked with ST's runtime library and timed with the DWT cycle counter.

| folder | board | clock and memory setup |
|---|---|---|
| `f401/` | NUCLEO-F401RE (Cortex-M4) | register level, 84 MHz from HSI, flash prefetch and caches on, no HAL |
| `h7b3/` | STM32H7B3I-DK (Cortex-M7) | ST's STM32H7B3I-DK template: direct SMPS, VOS0, 280 MHz, I/D-cache on, data in DTCM |

Run everything through `unas/local_bench.py`:

    python unas/local_bench.py --board f401 datasets/highd/results/deploy/<model>.tflite [...]
    python unas/local_bench.py --board h7b3 datasets/dmir/results/deploy/<model>.tflite [...]

Each file is generated (`stedgeai generate --target stm32 --c-api legacy`, default options:
balanced, I/O in the activation buffer), built, flashed over SWD and timed: 5 warm-up and 200
timed `ai_network_run` calls with fresh pseudo-random inputs and no interrupts. The firmware
writes its result block (`g_result`: magic, core clock, runs, min/mean/max cycles, status,
loop counter) to RAM, and the script reads it over SWD, so the virtual COM port may stay
open in another program. One JSON line per file goes to
`datasets/<dataset>/results/deploy/local_bench.jsonl`. After the timed runs the board keeps
running inferences in a loop, for current measurements (NUCLEO: IDD jumper JP6).

`h7b3/` also builds with `make CHECK=1 GEN=../build/gen/<tag>` (activations in AXI SRAM): after the
timed runs it runs the input tensors of `build/check/check_io.h` (`CHECK_N`, `check_in`) once each and
keeps the raw output bytes in `g_check_out` for an SWD read, to compare the board's outputs with the
host build of the same generated code. The header holds real test inputs, so it is generated into
`build/` and never versioned.

Tools (paths in the Makefiles and the script; this machine): ST Edge AI Core 4.0.0
(`C:\ST\STEdgeAI\4.0`), STM32CubeIDE 2.1.1 (GCC 14.3.1, make), STM32CubeProgrammer 2.22,
STM32CubeH7 1.13.0 (from STM32CubeMX). Not versioned: `third_party/` (ST's CMSIS F4 device
files, fetched from github.com/STMicroelectronics/cmsis-device-f4) and `build/` (generated
code, which for highD and exiD models embeds nothing from the datasets, and the images).
